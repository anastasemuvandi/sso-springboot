# Keycloak login + email theme (Keycloakify)

SPEC §1 (Login theme row), §3, §5.7, §5.12, §6 "Other React surfaces".
Port of the reference FreeMarker themes `sso/themes/government-citizens` and
`sso/themes/gor-admin` to Keycloakify 11.16.3 (React 18 + TS + Vite).

## Build

```bash
export PATH=$PWD/.tools/node/bin:$PATH          # from repo root
cd keycloak-theme && npm ci
npm run typecheck                                # tsc --noEmit
npm test                                         # vitest (pure helpers)
npm run build                                    # tsc + vite build
npm run build-keycloak-theme                     # -> dist_keycloak/gorsso-keycloak-theme.jar (needs mvn)
scripts/smoke.sh                                 # docker: KC 26.2 + jar, curls both variants
```

Output: `keycloak-theme/dist_keycloak/gorsso-keycloak-theme.jar` (Keycloak 26.x target;
the 22–25 jar is disabled). Copy it to `/opt/keycloak/providers/` before `kc.sh build`
(`keycloak/Dockerfile`).

## Themes in the jar

| Theme name | Types | Look |
|---|---|---|
| `government-citizens` | login, email | Reference citizens theme: PatternFly 4 underneath (Keycloak common resources, *not* keycloak's `css/login.css`) + ported `login.css`; split screen, "Government of Rwanda / Single Sign-On", flag-palette arcs, `footerNotice`. |
| `gor-admin` | login, email | Reference admin theme: no PatternFly; every `kc*Class` remapped to `gor-*` (as its `theme.properties` did) + ported `login.css` (incl. dark mode); "Government of Rwanda SSO / Administration portal", feature list, `gorAdminFooter`. |

One bundle; branding switches on `kcContext.themeName` (`src/login/branding.ts`).
Unknown names fall back to citizens. All realm JSONs in `configs/realms/` currently use
`loginTheme: government-citizens`; `gor-admin` is available for the admin realm.

## Environment variables (Keycloak container)

| Var | Effect |
|---|---|
| `GORSSO_ACCOUNT_SETUP_URL` | Wrapper's resend page. Keycloakify `environmentVariables` writes `GORSSO_ACCOUNT_SETUP_URL=${env.GORSSO_ACCOUNT_SETUP_URL:}` into `theme.properties` (same mechanism as the reference `gorAccountSetupUrl`), read as `kcContext.properties.GORSSO_ACCOUNT_SETUP_URL`. Empty/unset → link hidden. Full URL expected (`https://sso.gov.rw/account/setup-link`); a bare origin gets `/account/setup-link` appended; non-http(s) is ignored. |

The link ("Didn't get the email to set your password? Send it again") shows on
`login`, `login-username`, `login-password` only, with `?lang=<locale>&username=<attempted>&return_to=<loginRestartFlowUrl>`
exactly as the reference (`return_to` is Keycloak's relative restart URL).

## Pages

- Custom: `login.ftl` (`src/login/pages/Login.tsx`, SVG password reveal),
  `login-otp.ftl` (`LoginOtp.tsx`, adds `#gor-otp-help` / `gorOtpLoginHelp`),
  `info.ftl` (`Info.tsx`, adds `#gor-account-ready` after "Your account has been updated.").
- Shared shell `src/login/Template.tsx`: brand, locale switcher, username context +
  restart link, alert, try-another-way, social providers, setup link, info, footer, brand
  panel, lockout hint. Keycloak's `authChecker.js` session polling is kept
  (`useGorInitialize.ts`).
- Everything else is Keycloakify's default page in our Template + variant classes:
  login-username, login-password, login-reset-password, login-update-password,
  login-update-profile, error, logout-confirm, login-config-totp (QR + "type a key" manual
  mode), login-recovery-authn-code-config, login-recovery-authn-code-input,
  select-authenticator, terms, login-page-expired, etc.
- Lockout (§3: 5 failures, 900 s): `accountTemporarilyDisabledMessage` overridden (citizens
  says "Try again in 15 minutes"), and `#gor-lockout-hint` ("5 failed attempts … lock the
  account for 15 minutes") appears on login/login-username/login-password/login-otp/
  recovery-code-input whenever an error is shown (`src/login/lockout.ts`). Keycloak itself
  usually answers a locked account with the generic invalid-credentials error (no oracle).

## i18n

`src/login/i18n.ts` — every key of the reference `messages_en/rw.properties` of both
themes, plus `gorLockoutHint`; per-variant values where the two bundles differ. Kinyarwanda
is an extra Keycloakify language (`withExtraLanguages`); its base set
(`src/login/i18n.rw.ts`, generated by `scripts/gen-rw-base.mjs`) is English, as in the
reference where un-overridden rw keys fell back to English. Keycloakify writes the merged
strings into `messages_<lang>.properties` per theme, so server-rendered messages
(`invalidUserMessage`, `configureTotpMessage` …) are translated too.
Brand-panel copy stays hard-coded English (decorative, `aria-hidden`), as in the reference.

## Email theme

Native FreeMarker under `src/email/` (Keycloakify copies it into both theme names):
branded `html/template.ftl` (flag strip, header, footer; inline styles, no remote images),
`password-reset`, `email-verification`, `executeActions` (html + text), and
`messages_{en,rw}.properties` (subjects, bodies, `requiredAction.UPDATE_PASSWORD/
CONFIGURE_TOTP/...`, rw link-expiry units). Reference had no email templates. Takes
effect only when a realm sets `emailTheme` (SPEC §3 sets only `loginTheme` today).

## Tests

- `src/login/branding.test.ts`, `setupLink.test.ts`, `lockout.test.ts` — 20 Vitest tests
  (variant/branding, subtitle rule, setup-link visibility/URL building/encoding/scheme
  guard, lockout hint rule, info "account ready" match).
- `scripts/smoke.sh` — starts `quay.io/keycloak/keycloak:26.2` with the jar in
  `/opt/keycloak/providers`, imports two throwaway realms (one per theme, en+rw, brute force
  5/900 s), curls the auth endpoint and checks pageId/themeName/setup URL/rw locale, and
  checks both names are registered as login *and* email themes. Passed on 26.2.5.
- Manually verified once in headless Chromium (not committed): both variants render en/rw
  with no console errors; wrong password shows the error + lockout hint; CONFIGURE_TOTP
  renders the QR enrolment page.

## Gaps / follow-ups (outside `keycloak-theme/`)

- Realm JSONs: `government-internal` lists `en, fr, rw`; `government-citizens` lists
  `en, fr`; `government-admin` has i18n off. Spec wants en + rw — someone owning
  `configs/realms/` should set `supportedLocales: ["en","rw"]` (and `emailTheme`, and
  `loginTheme: gor-admin` for the admin realm if wanted).
- French: the reference citizens theme had `messages_fr`; not ported (spec is en + rw).
  In `fr` the GoR-overridden keys fall back to the English custom text.
- Kinyarwanda strings (reference ones and the new lockout/email ones) still need a
  native-speaker review, as the reference already noted.
- No Inter webfont link (reference admin deliberately avoided it for air-gapped hosts; the
  citizens theme linked Google Fonts — dropped here, system font stack fallback).
- No Storybook / visual regression tests.
